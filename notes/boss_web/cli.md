# `boss_web.cli` 协议笔记

> 摘自 `boss_web/cli.py` 的模块文档字符串 / `#` 注释 / 函数文档字符串。

## 一句话

网页控制台的命令行入口：`python -m boss_web`。

## 细节

打包成 exe 后这个入口由 `run_boss.py` 调用，两者的差别只在 uvicorn 的启动方式（见 `main` 里的 `frozen` 分支）。

冻结环境里不能用 Uvicorn 的字符串导入 + reload：那会 re-exec `sys.executable` 起子进程，而 exe 并不是一个有意义的 Python 解释器。

### `_open_browser_when_ready`

等 uvicorn 真的起来、登录态自检出结果，再开浏览器。

原来是在 `uvicorn.run` **之前**开，用户会先看到一个连接被拒的页面，得手动刷新——对不懂的人是「这软件坏了」。

`ready` 是登录态自检的完成信号（`session_check.schedule_startup_check` 返回的那个）。默认**等它出结果再开**：否则首屏会话卡片会先渲染一份没验过的状态，用户看到「离线」，刷新一次才正确。自检卡住（断网、接口慢）也不会把浏览器无限期扣住——到点照样开。

### `main` 启动序

- 存过的 Chrome 窗口档位要写回环境变量。必须早于任何取令牌的调用——`boss_jobs` 是在调用时才读的，晚一步就白设。
- 自更新要能「从里往外」把 uvicorn 停掉：挂上这个引用，bat 那边触发 `request_exit` 时才不会只能硬 `os._exit`（端口都来不及干净释放）。
- 版本检测后台预热：开页面时就有结果，不用先卡 8 秒等 Gitee；测完把「当前 / 发行 / 要不要更新」补打在横幅下面。
- 之后每 5 分钟再测一次：挂机也能发现新版（前端只做轻提示，不弹窗）。
- 登录态自检：启动时拿库里的凭证打一次用户信息接口，过期就把库里的清掉。开浏览器之前等它出结果——否则首屏会话状态没验过，用户看到「离线」，得刷新一次才对（见 `_open_browser_when_ready` 的 `ready` 参数）。

### `_self_check`

把打包后「开发态验不了」的东西打出来：资源根、前端目录、库路径、Chrome。在 cmd 里跑 `BossAutoDelivery.exe --self-check` 就能核对，不用真开浏览器。

自检也把版本对比打出来：用户核对打包完整性时顺手看一眼有没有新版。
